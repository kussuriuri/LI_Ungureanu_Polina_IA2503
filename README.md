## 1. Запуск проекта

### Что нужно

- PHP 8 или новее с расширением `pdo_pgsql`
- PostgreSQL

Проверить расширение: `php -m | grep pdo_pgsql`

### Шаги

1. Склонировать репозиторий и перейти в папку проекта:
   ```
   git clone https://github.com/ЛОГИН/bento-cake-studio.git
   cd bento-cake-studio
   ```
2. Создать базу данных и таблицы (схема уже содержит тестовые торты и начинки):
   ```
   createdb bento
   psql -d bento -f schema.sql
   ```
3. Проверить параметры подключения в `config.php` (хост, порт, имя базы, пользователь, пароль). По умолчанию: `localhost`, `5432`, `bento`, пользователь `polina`, пароль пустой. Если у вас другой пользователь PostgreSQL, замените его.
4. Запустить встроенный сервер PHP, указав `public` корневой папкой:
   ```
   php -S localhost:8000 -t public
   ```
5. Открыть в браузере http://localhost:8000

### Как получить права администратора

Администраторов нет, пока они не созданы. Зарегистрируйтесь на сайте как обычный пользователь, затем выполните:

```
psql -d bento -c "UPDATE users SET role = 'admin' WHERE email = 'ваш@email.com';"
```

После этого войдите заново, в меню появится пункт «Админ-панель». Дальше новых администраторов можно создавать прямо из панели.

### Частые проблемы

| Ошибка | Что делать |
|---|---|
| `database "bento" does not exist` | выполнить `createdb bento` и `psql -d bento -f schema.sql` |
| `could not find driver` | включить расширение `pdo_pgsql` в PHP |
| `password authentication failed` | поправить `user` и `password` в `config.php` |
| на `/` ошибка 404 | сервер запущен без `-t public` |
| вместо картинок значок 🍰 | в `public/images/` нет файла с таким именем, как в колонке `cakes.image` |

## 2. Описание работы

**Задача.** Разработать веб-приложение средней сложности с серверной логикой на PHP, базой данных, аутентификацией, двумя формами, защищённым разделом с ролью администратора и модульной архитектурой.

**Предметная область.** Кондитерская мастерская бенто-тортов: небольших тортов на одну-две порции. Клиент выбирает торт, начинку и декор, указывает надпись и дату получения. Администратор ведёт каталог, заказы и пользователей.

**Стек:** PHP 8, PostgreSQL, PDO, HTML, CSS, PHP-шаблоны (без шаблонизатора), небольшой фрагмент JavaScript на странице заказа.

## 3. Документация проекта

### 3.1. Содержание

Приложение состоит из трёх частей:

- **публичная часть:** главная, каталог с поиском, страница торта, регистрация и вход;
- **раздел клиента:** оформление заказа и список своих заказов;
- **административная панель:** тортами, заказами и пользователями.

#### Структура проекта

```
├── public/                 страницы (точки входа)
│   ├── index.php           главная
│   ├── catalog.php         каталог и поиск
│   ├── cake.php            страница торта
│   ├── register.php, login.php, logout.php
│   ├── order.php           оформление заказа
│   ├── my_orders.php       заказы клиента
│   ├── admin.php           главная админ-панели
│   ├── admin_cakes.php, admin_cake_add.php, admin_cake_edit.php
│   ├── admin_orders.php, admin_users.php, admin_create_admin.php
│   └── images/             картинки тортов
├── src/                    логика
│   ├── Database.php        подключение к PostgreSQL (PDO)
│   ├── functions.php       общие функции: getPdo(), h(), getErrors() и др.
│   ├── auth.php            пользователи, сессии, вход и выход
│   ├── cakes.php           торты и начинки, поиск
│   ├── orders.php          заказы, расчёт стоимости
│   ├── users.php           управление пользователями
│   ├── handler.php         обработчики действий
│   ├── Validator.php       проверка данных форм
│   └── RegisterForm.php, LoginForm.php, OrderForm.php,
│       CakeForm.php, SearchForm.php
├── templates/              шаблоны (только вывод)
│   ├── layout.php          общий макет: шапка, меню, подвал
│   ├── home.php, catalog.php, cake.php, cake_card.php
│   ├── login.php, register.php, order_form.php, my_orders.php
│   └── admin/              шаблоны админ-панели
├── config.php              параметры подключения к БД
└── schema.sql              создание таблиц и начальные данные
```

**Принцип разделения.** Страница из `public/` принимает запрос, вызывает функции из `src/` и подключает `layout.php`. Шаблон выводит данные и ничего не считает. В `src/` нет HTML.

**Как обрабатывается запрос:**

1. Браузер обращается к странице из `public/`.
2. Страница подключает `src/functions.php` и `src/handler.php`.
3. Обработчик читает данные формы, проверяет их через `Validator` и при необходимости обращается к базе.
4. Страница собирает переменные (`$title`, `$data`, `$errors` и др.) и список шаблонов `$parts`.
5. `layout.php` выводит шапку и подключает шаблоны из `$parts`.

### 3.2. Функциональные возможности

**Гость**
- просмотр главной, каталога и страниц тортов;
- поиск по названию, вкусу, диапазону цены и наличию;
- регистрация и вход.

**Клиент** (всё, что гость, плюс)
- оформление заказа: торт, начинка, декор, надпись, дата получения, пожелания, подарочная упаковка;
- список своих заказов с суммой и статусом.

**Администратор** (всё, что клиент, плюс)
1. создание новых администраторов;
2. добавление тортов;
3. редактирование тортов, снятие с продажи;
4. удаление тортов;
5. просмотр всех заказов и смена статусов (новый, готовится, готов, выдан, отменён);
6. управление пользователями: смена роли, удаление.

**Ограничения, заложенные намеренно**
- торт с заказами удалить нельзя, его нужно снять с продажи (иначе потеряется история заказов);
- администратор не может изменить роль или удалить свою учётную запись;
- заказы через интерфейс не удаляются;
- дата получения: не раньше чем через 2 дня и не позже чем через 60 дней.

### 3.3. Сценарии взаимодействия

**Поиск в каталоге.** Пользователь вводит часть названия, выбирает вкус, указывает цену «от» и «до» и нажимает «Найти». Параметры передаются GET-запросом, `SearchForm` их проверяет, `searchCakes()` собирает SQL только из заполненных условий. Если цена «от» больше цены «до», показывается ошибка; если ничего не найдено, сообщение об этом.

**Регистрация.** Гость заполняет имя, email, пароль и его повтор. Проверяются формат полей, длина и надёжность пароля (буква и цифра), совпадение паролей и уникальность email. Пароль сохраняется как хеш, пользователь попадает на страницу входа.

**Вход.** Пользователь вводит email и пароль. Если пара верная, меняется идентификатор сессии и в неё записывается ID пользователя. При ошибке выводится одно общее сообщение «Неверный email или пароль».

**Оформление заказа.** Клиент выбирает торт (над формой показывается его картинка), начинку, декор, при желании вводит надпись и пожелания, выбирает дату и упаковку. Сервер проверяет значения, считает сумму как цена торта плюс доплата за начинку плюс упаковка (100 лей) и сохраняет заказ. Затем открывается «Мои заказы».

**Мои заказы.** Из базы выбираются только заказы текущего пользователя вместе с названиями тортов и начинок.

**Управление тортами (админ).** Администратор добавляет или редактирует торт через форму с серверной проверкой. При удалении приложение сначала проверяет, есть ли заказы на этот торт.

**Заказы и пользователи (админ).** Статус заказа меняется выпадающим списком, сервер принимает только допустимые значения. В списке пользователей можно сменить роль или удалить учётную запись, кроме собственной.

### 3.4. Структура базы данных

База `bento`, четыре таблицы.

**users** — пользователи

| Поле | Тип | Назначение |
|---|---|---|
| id | SERIAL, PK | идентификатор |
| name | VARCHAR(50) | имя |
| email | VARCHAR(100), UNIQUE | email |
| password_hash | VARCHAR(255) | хеш пароля |
| role | VARCHAR(10) | `client` или `admin` (CHECK) |
| created_at | TIMESTAMP | дата регистрации |

**fillings** — начинки

| Поле | Тип | Назначение |
|---|---|---|
| id | SERIAL, PK | идентификатор |
| name | VARCHAR(50) | название |
| description | TEXT | описание |
| extra_price | INT | доплата, не меньше 0 (CHECK) |

**cakes** — торты

| Поле | Тип | Назначение |
|---|---|---|
| id | SERIAL, PK | идентификатор |
| title | VARCHAR(50) | название |
| flavor | VARCHAR(50) | вкус |
| description | TEXT | описание |
| price | INT | цена, больше 0 (CHECK) |
| is_available | BOOLEAN | есть ли в продаже |
| image | VARCHAR(255) | имя файла в `public/images/` |
| created_at | DATE | дата добавления |

**orders** — заказы

| Поле | Тип | Назначение |
|---|---|---|
| id | SERIAL, PK | идентификатор |
| user_id | INT, FK → users | клиент |
| cake_id | INT, FK → cakes | торт |
| filling_id | INT, FK → fillings | начинка |
| decor | VARCHAR(20) | `minimal`, `flowers`, `berries`, `retro` (CHECK) |
| inscription | VARCHAR(40) | надпись |
| pickup_date | DATE | дата получения |
| comment | TEXT | пожелания |
| gift_box | BOOLEAN | подарочная упаковка |
| total_price | INT | итоговая сумма |
| status | VARCHAR(20) | `new`, `in_progress`, `ready`, `done`, `cancelled` (CHECK) |
| created_at | TIMESTAMP | время создания |

**Связи**

```
users 1 ──── N orders N ──── 1 cakes
                    N
                    │
                    1
                 fillings
```

Один пользователь, торт и начинка могут встречаться во многих заказах. Таблица `orders` связывает остальные три.

**Целостность.** Используются PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, CHECK и DEFAULT. При удалении пользователя его заказы удаляются каскадом (`ON DELETE CASCADE`). Для тортов каскада нет: торт с заказами не удаляется.

## 5. Ответы на контрольные вопросы

**1. Чем GET отличается от POST?**
GET передаёт параметры в адресной строке и подходит для запросов, которые только читают данные (поиск в каталоге). POST отправляет данные в теле запроса и используется для действий, которые что-то меняют: регистрация, вход, заказ, действия администратора. Сам по себе POST не делает данные безопасными, сервер всё равно проверяет их.

**2. Зачем нужны подготовленные запросы?**
В них SQL-команда и значения передаются отдельно. Введённая пользователем строка не становится частью SQL, поэтому её нельзя использовать для SQL-инъекции.

**3. Как хранятся пароли?**
Только в виде хеша: при регистрации вызывается `password_hash()`, при входе введённый пароль проверяется через `password_verify()`. Хеш содержит случайную соль, поэтому у одинаковых паролей разные хеши, а восстановить пароль из хеша нельзя.

**4. Что такое сессия и что в ней хранится?**
HTTP не помнит предыдущих запросов, поэтому после входа сервер создаёт сессию. В ней хранится только ID пользователя, а имя и роль приложение берёт из базы при каждом запросе. Если роль изменить, это сразу действует.

**5. Зачем менять идентификатор сессии после входа?**
Чтобы злоумышленник не мог заранее подсунуть пользователю известный ему ID сессии и затем войти под ним (фиксация сессии). Это делает `session_regenerate_id(true)`.

**6. Чем аутентификация отличается от авторизации?**
Аутентификация отвечает на вопрос «кто это», она происходит при входе по email и паролю. Авторизация отвечает на вопрос «что ему можно»: проверка роли `client` или `admin` через `requireLogin()` и `requireAdmin()`.

**7. Что такое XSS и как защищена работа?**
Это внедрение чужого скрипта через пользовательский ввод. Весь выводимый текст проходит через `h()` (`htmlspecialchars`), поэтому вставленные теги отображаются как обычный текст, а не выполняются.

**8. Зачем проверять данные и на клиенте, и на сервере?**
Проверка в браузере (атрибуты `required`, `minlength`, `type="email"`, `min`, `max`) удобна для пользователя, но её можно отключить или обойти прямым запросом. Серверная проверка в `Validator` обязательна. Именно поэтому сервер проверяет даже значения выпадающих списков и переключателей.

**9. Почему сумма заказа считается на сервере?**
Если бы цена приходила из формы, её можно было бы изменить. Сервер берёт цены торта, начинки и упаковки из базы и считает итог сам.

**10. Что такое первичный и внешний ключ?**
Первичный ключ однозначно определяет запись в таблице (`id`). Внешний ключ ссылается на запись другой таблицы: `orders.user_id` указывает на `users.id`, поэтому у каждого заказа есть клиент.

**11. Зачем нужен `ON DELETE CASCADE`?**
Если удалить пользователя, его заказы удаляются автоматически, и в базе не остаётся заказов без владельца. Для тортов каскада нет специально: торт с заказами нельзя удалить, чтобы не потерять историю.

**12. Что такое CRUD?**
Четыре базовые операции с данными: создание, чтение, изменение, удаление. В проекте это полностью реализовано для тортов, для пользователей (чтение, изменение роли, удаление, создание администратора) и частично для заказов (создание, чтение, смена статуса).

**13. Зачем нужно разделение на `public`, `src` и `templates`?**
Чтобы не смешивать логику и вывод. Страницы только принимают запрос и собирают данные, логика находится в `src/`, а шаблоны только выводят готовые переменные. Любой слой проще менять независимо.

**14. Для чего нужен `layout.php`?**
Это общий каркас страницы: шапка, меню, основная область и подвал. Страница передаёт ему список шаблонов `$parts`, и он подключает их внутри основной области. Благодаря этому разметка шапки не повторяется на каждой странице.

**15. Что означает статус 404 и где он используется?**
Страница не найдена. Он возвращается, например, на `cake.php` и `admin_cake_edit.php`, если идентификатор торта неверный или такого торта нет.

## 7. Другие важные аспекты

**Безопасность: что сделано**
- подготовленные запросы PDO;
- экранирование всего вывода;
- хеширование паролей;
- проверка роли на сервере на каждой закрытой странице;
- cookie сессии с флагами `HttpOnly` и `SameSite=Lax`, смена ID сессии при входе;
- валидация всех данных на сервере, включая допустимые значения списков.

**Ограничения и что можно улучшить**
- не реализовано восстановление пароля по почте (дополнительное задание);
- нет защиты форм от CSRF-атак (токенов в формах нет), как и ограничения числа попыток входа;
- картинки тортов добавляются вручную в папку `public/images/` и прописываются в базе, загрузки через интерфейс нет;
- длинные списки (каталог, заказы, пользователи) не разбиваются на страницы.

**Картинки.** В колонке `cakes.image` хранится имя файла из `public/images/`. Если файла нет, на сайте показывается значок 🍰. Новый торт, добавленный через админ-панель, пока отображается без картинки.

**Часовой пояс.** Даты считаются по `Europe/Chisinau` (задан в `src/functions.php`), от этого зависит допустимый диапазон дат получения заказа.
